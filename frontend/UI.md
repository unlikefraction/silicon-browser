# Silicon UI

Browser's interface is built from the real Silicon UI components (https://ui.teamofsilicons.com), installed verbatim from the registry. They are rendered client-only in a Next.js Pages Router static export.

- **Install set.** The set is pinned in `src/components/silicon-ui/registry-lock.json`: one `{url, sha256}` per registry item, transitive registry dependencies included. `node scripts/sync-silicon-ui.mjs` downloads every item, verifies its sha256, writes each file byte-for-byte to `src/components/silicon-ui/…`, and removes files that no locked item provides. `--check` verifies the tree without writing, and `--update` records new hashes after a reviewed upstream change. Registry files are never edited by hand.
- **Foundation.** `foundation.css` is imported once in `src/pages/_app.tsx`. `<html>` carries `data-accent="neutral"` and `data-corners="squircle"`. `public/boot.js` sets `data-theme` (light or dark) before first paint. The setting comes from `localStorage['silicon-browser:theme']`, or from `prefers-color-scheme` when nothing is stored. The account menu's theme switch stores the choice; System clears it.
- **Fonts.** Geist and Inter variable fonts are self-hosted from `@fontsource-variable/*`, latin subset only (`src/browser/styles/fonts.css`, OFL-1.1).
- **CSP.** Silicon UI, motion and Radix write runtime styles, so the policy allows `style-src 'self' 'unsafe-inline'`. Scripts stay `script-src 'self'`: the export contains no executable inline script, and `scripts/check-export.mjs` fails the build if one appears.
- **Built from tokens where Silicon UI has no component.** Rail navigation, the account switcher, page headers, definition lists, panels, and anchors styled as buttons (`ButtonLink`, `ExternalButtonLink`) live in `src/browser/ui` and `src/browser/shell`. `global.css` adds one app token, `--font-mono` (the stack CodeBlock uses), for ids and UUIDs.
- **Headings.** Every view has one `<h1>` (`PageHeader`). Card and EmptyState titles are `<h3>`, so lists sit inside `ListSection`, which adds a visually hidden `<h2>` and keeps the outline in order.
- **Consumer overrides (no registry file is edited).** `SortableDataTable` keeps a 560px minimum width and scrolls inside its frame; with the rail beside the content (721–830px) that clipped the last columns, so the Sessions and Usage screens set `min-width: 0` on their table (and pad its rows so wrapped text clears the row lines), and the Sessions table hides the mono id between 621 and 900px (the id stays on the session page). `TagInput` keeps tags on one line, so the profile form lets a long UUID tag wrap at its hyphens. `MetricCard` has no `decimals`, so Usage draws the same card around `AnimatedCounter`. `TagInput` has no `name` or `disabled`: the form mirrors it into a hidden `access` input and disables it through a bare `<fieldset>`.
